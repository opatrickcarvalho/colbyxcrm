#### 1. Preparando o Banco de Dados para Grupos e Multi-Sessão

Nosso banco de dados atual possui duas limitações: aceita apenas um número de WhatsApp por conta e exige que toda conversa seja com um contato individual (1:1).

* **Múltiplos Números (Multi-Device):** Precisamos alterar as regras do banco de dados para permitir que o cliente conecte vários números na mesma conta (Considere o superadmin permitir quantos números cada conta pode trabalhar, no futuros será controlado por assinatura). Além disso, precisamos criar um campo para identificar a função de cada número (exemplo: "Número A faz atendimento", "Número B administra os grupos da Campanha X").
* **A Entidade 'Grupo':** Precisamos criar uma nova tabela dedicada aos Grupos. Essa tabela deve armazenar: a qual conta o grupo pertence, a qual "Campanha" ou "Segmento" ele faz parte, o link de convite, o número atual de participantes e a capacidade máxima desejada.
* **Ajuste nas Conversas:** Precisamos flexibilizar o sistema para entender que uma "conversa" pode acontecer com uma pessoa física OU com um grupo, relacionando essa conversa à nova tabela de Grupos.

#### 2. A Esteira de Captação (Roteamento Dinâmico)

Precisamos de um link único e inteligente para receber o tráfego das nossas landing pages e anúncios. O cliente nunca deve clicar diretamente no link do WhatsApp, mas sim no link do nosso sistema.

* **O Roteamento:** O lead acessa nosso link único informando qual campanha ele tem interesse. O sistema consulta o banco de dados buscando o grupo ativo mais antigo daquela campanha que ainda tenha vagas (participantes abaixo da capacidade máxima).
* **Se houver vaga (Transbordo invisível):** O sistema captura o link de convite daquele grupo específico e redireciona o usuário para lá automaticamente.
* **Se não houver vaga (Grupos lotados):** O sistema deve dar a instrução para a API do WhatsApp criar um grupo novo naquela hora, gerar o link de convite, salvar no banco de dados e só então redirecionar o usuário para este novo grupo.

#### 3. Escutando a Comunidade (Webhooks)

Hoje, nosso sistema ignora o que acontece dentro dos grupos. Precisamos passar a processar esses eventos para manter o banco de dados atualizado e proteger os leads.

* **Controle de Lotação em Tempo Real:** O sistema deve escutar os eventos de "pessoa entrou" e "pessoa saiu" do grupo. A cada evento, devemos atualizar o contador de participantes daquele grupo no banco de dados. Isso garante que a nossa esteira (item 2) nunca mande tráfego para um grupo cheio.
* **Filtro Anti-Spam (Proteção de Leads):** Precisamos de um filtro básico de segurança. Quando o sistema receber uma mensagem vinda de um grupo, ele deve verificar se o remetente é um Administrador. Se for um membro comum e a mensagem contiver um link (http/https), o sistema deve acionar a API do WhatsApp para deletar essa mensagem imediatamente, evitando que concorrentes ou golpistas roubem nossos leads.

#### 4. Automação de Comunidade (Abertura e Fechamento)

Durante lançamentos ou eventos, os grupos não podem ficar abertos para bate-papo o tempo todo.

* **Sistema de Agendamento:** Precisamos criar uma estrutura no banco de dados onde possamos agendar mudanças de permissão. Exemplo: "Programar para que amanhã, às 19:00, o Grupo VIP 01 seja Aberto (todos enviam mensagem), e às 21:00 seja Fechado (apenas admins enviam)".
* **Processamento da Fila:** Devemos criar uma rotina (um cron/gatilho programado) que rode periodicamente, olhe para esses agendamentos pendentes e, no momento exato, dispare a instrução para a API do WhatsApp alterar as configurações do grupo.

#### 5. Interface de Gestão (Painel do Administrador)

* Precisamos de telas no nosso painel de controle onde o administrador consiga visualizar todos os seus grupos, organizados e filtrados por campanhas.
* Esse painel deve exibir uma barra de progresso mostrando a lotação de cada grupo (ex: 850/1000 vagas).
* Deve haver também a opção de criar novas campanhas e configurar novos grupos manualmente pela interface.
